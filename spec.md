# spec.md

AIExplain project notes specification for Codex-compatible AI assistants.

## Project Purpose

This project stores human-readable notes from working experience so lay people can understand AI topics such as RAG, fine-tuning, OCR, embeddings, and related practical knowledge.

## Writing Rules

- Keep the author's core concept unchanged.
- Keep the original line order unless the user explicitly asks to reorganize it.
- Prefer simple words over academic wording.
- Write for non-technical readers first.
- Preserve practical working-experience examples.
- Correct spelling or grammar only when the user asks, or when it does not change meaning.
- Do not make the notes sound like marketing content.

## File Rules

- Use Markdown files for notes.
- Use clear topic-based filenames.
- Keep one main topic per note file when possible.
- Add headings only when they improve readability and do not change the author's intended flow.

## Workflow

Before changing existing notes:

1. Read the target note first.
2. Understand the author's intended explanation.
3. Keep meaning and sequence intact.
4. Make only the requested changes.
5. Summarize what changed.

## Version Control

- Do not commit or push unless the user explicitly asks for that exact action.
- Read-only Git commands are allowed.
- Leave changes for the user to review.
